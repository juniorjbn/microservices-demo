O que é esse app?

O Online Boutique é uma loja virtual fictícia criada pelo Google para demonstrar o modelo de microsserviços: em vez de um programa monolítico, o app é dividido em 11 serviços pequenos e autônomos, escritos em 6 linguagens diferentes, cada um com uma responsabilidade bem definida. Eles conversam entre si via gRPC.

Este fork customiza a loja para o público brasileiro:
🇧🇷 Idioma: site em português (pt-BR) com suporte a inglês (en) · 💰 Moeda: BRL (Real) como padrão, formatação brasileira (R$ 1.234,56) · 🎨 Design: frontend redesenhado com CSS Grid, fonte Geist, nav minimalista

Os serviços

Cada serviço tem um papel único. Juntos eles formam a loja completa.

gRPC HTTP (navegador) Redis (cache)
Go frontend

Monta e serve a página da loja. É a única interface que o usuário enxerga. Coordena todos os outros serviços para exibir produtos, preços, carrinho e anúncios.

Porta 8080 (HTTP) · Chama: todos os demais serviços
C# cartservice

Mantém o carrinho de compras do usuário. Cada item adicionado ou removido passa por aqui. Os dados ficam armazenados no Redis.

Porta 7070 · Usa: Redis
Go productcatalogservice

Guarda o catálogo de produtos: nomes, preços, descrições e imagens. É consultado por vários serviços, mas nunca modifica os dados.

Porta 3550 · Chama: nenhum
Node currencyservice

Converte valores entre moedas (dólar, euro, real, iene…). Usa taxas reais do Banco Central Europeu salvas em arquivo estático.

Porta 7000 · Chama: nenhum
Node paymentservice

Processa o pagamento com cartão de crédito (simulado — nenhum dinheiro é cobrado). Retorna um identificador de transação.

Porta 50051 · Chama: nenhum
Go shippingservice

Calcula o frete e simula o envio do pedido. Devolve uma estimativa de custo e prazo de entrega.

Porta 50051 · Chama: nenhum
Python emailservice

Envia o e-mail de confirmação do pedido (modo simulado — apenas imprime no log). Usa um template HTML para formatar a mensagem.

Porta 8080 · Chama: nenhum
Go checkoutservice

Orquestra a finalização da compra: consulta o carrinho, calcula frete, cobra o cartão, envia o e-mail. É o maestro do checkout.

Porta 5050 · Chama: productcatalog, cart, currency, shipping, payment, email
Python recommendationservice

Sugere produtos com base no carrinho ("quem comprou isso também comprou…"). A seleção é aleatória, filtrada pelos itens já presentes.

Porta 8080 · Chama: productcatalogservice
Java adservice

Exibe anúncios de acordo com o contexto do produto. Retorna até dois anúncios aleatórios de um mapa pré-definido em memória.

Porta 9555 · Chama: nenhum
Redis redis-cart

Banco de dados em memória que persiste os carrinhos de compra. Toda alteração no carrinho passa por ele.

Porta 6379
Python loadgenerator

Simula centenas de usuários acessando a loja simultaneamente. Usa a ferramenta Locust para gerar tráfego e testar a resiliência do sistema.

Chama: frontend (HTTP)

Fluxo de uma requisição

Quando você abre a página inicial, o frontend orquestra uma série de chamadas para montar a loja que você vê.

  1. Frontend pede a lista de moedas → currencyservice
  2. Frontend pede o catálogo de produtos → productcatalogservice
  3. Frontend busca o carrinho do usuário → cartservice → Redis
  4. Frontend converte os preços → currencyservice
  5. Frontend solicita anúncios → adservice
  6. Frontend renderiza o HTML final → envia ao navegador

Ao finalizar a compra, o frontend chama o checkoutservice, que coordena o resto: busca o carrinho, calcula frete, processa o pagamento e envia o e-mail de confirmação.

Deploy no Kubernetes com Helm

O Helm é o gerenciador de pacotes do Kubernetes. Com dois comandos você sobe a loja completa no seu cluster.

Pré-requisitos

# Verificar se o cluster está rodando
$ kubectl cluster-info

# Verificar versão do Helm
$ helm version

# Login no Docker Hub (imagens + Helm chart OCI)
$ docker login
$ helm registry login registry-1.docker.io --username juniorjbn

Build e push das imagens + chart (Docker Hub)

Builda todos os 11 microsserviços, o Helm chart, e envia para Docker Hub.

# Login (se ainda não fez)
$ docker login
$ helm registry login registry-1.docker.io --username juniorjbn

# Buildar e fazer push de todas as imagens
$ ./build.sh

# Publicar o Helm chart no Docker Hub (OCI)
$ ./publish-chart.sh

Deploy com suas imagens (Docker Hub)

Builda e faz push das imagens para o Docker Hub, depois faz deploy no Kind.

# 1. Criar cluster Kind
$ kind create cluster --name onlineboutique

# 2. Buildar e fazer push das imagens
$ ./build.sh

# 3. Fazer deploy
$ ./deploy.sh

# 4. Acompanhar os pods
$ kubectl get pods -n onlineboutique -w

# 5. Acessar (port-forward)
$ kubectl port-forward -n onlineboutique \
    svc/frontend 8080:80

# Abra http://localhost:8080

Deploy rápido (Kind + imagens + chart no Docker Hub)

Pula o build local e usa tudo já disponível em juniorjbn/*:v1.0.0.

# Criar cluster
$ kind create cluster --name onlineboutique

# Deploy via helm (chart do Docker Hub OCI)
$ ./deploy.sh

# Port-forward (Kind não tem LoadBalancer)
$ kubectl port-forward -n onlineboutique \
    svc/frontend 8080:80

# Acesse: http://localhost:8080
Comandos úteis
$ kubectl get pods -n onlineboutique
$ kubectl logs -n onlineboutique deployment/frontend
$ kubectl port-forward -n onlineboutique svc/frontend 8080:80

# Remover tudo
$ helm uninstall onlineboutique -n onlineboutique
$ kubectl delete namespace onlineboutique

Deploy sem Helm (kubectl direto)

Os manifests estão na pasta kubernetes-manifests/.

$ kubectl apply -f kubernetes-manifests/
$ kubectl get pods

# Acessar via LoadBalancer
$ kubectl get svc frontend-external
